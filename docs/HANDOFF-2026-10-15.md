## (a) What this project is

**PlantVision** = a minimal, working slice of a vertical-farm monitoring system, built as
a step-by-step GitHub-committed curriculum. One Android phone (IP Webcam) photographs one
leafy-green plant at a fixed mount; a small host pulls each frame, deduplicates by content
hash, files the original + a JSON sidecar, logs the run, and (later) measures growth.
Deliberately minimal so it survives contact with reality (`README.md`, `task/reflection.md`).

## (c) What WORKS end-to-end + how to reproduce ONE capture

Flow: **phone snapshot** → `pull.fetch_photo` → `metadata.build_metadata` → `store.store_original`
(idempotent by sha256) → sidecar + JSONL log.

**Setup (fresh machine):**
```sh
git clone https://github.com/MariganMarigam/plantvision-lab.git
cd plantvision-lab
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"      # Windows: .venv\Scripts\python -m pip install -e ".[dev]"
```

**Point the config at the phone** (edit `configs/capture.yaml`):
```yaml
source_url: "http://<phone-ip>:8080/photo.jpg"   # e.g. http://192.168.1.5:8080/photo.jpg
```

**Reproduce a single capture (Linux):**
```sh
.venv/bin/python -m plantvision.capture.capture_once --config configs/capture.yaml
```
Expected: prints JSON `{"status":"ok","sha256":"…","path":"data/originals/phone-01/shelf-a_tray-1/<day>/…jpg"}`
and writes one `.jpg` + one `.json` sidecar under `data/originals/<camera_id>/<zone>/<day>/`;
one line appended to `data/capture.log`. Running twice on the same bytes → `{"status":"duplicate"}`.

**Tests:** `.venv/bin/python -m pytest -q` → `23 passed`.

**Status values** (`data/capture.log`, JSONL): `ok` | `duplicate` | `skipped_dark` | `gap` | `spooled`.

## (g) FORWARD ROADMAP (methodology; theory refs are `task/practic_CV.txt:<line>`)

> Guiding caveat (`reflection.md:119`, `reflection.md:487`): **pixels are not biomass** — projected
> area is a 2-D proxy; real mass/volume needs calibration and, for volume, additional views.

### G1 — Leaf area / volume methodology  (roadmap stages 05–06)
- **Goal:** turn each frame into comparable numbers: projected leaf area (px² and cm²), ROI-fraction %,
  crown width/height, day-over-day change; extend to **LAI** (Leaf Area Index) and plant **volume**.
- **Inputs:** `data/originals/…/*.jpg` + sidecar; the in-frame ArUco marker for px→cm scale.
- **Rough method:**
  1. Segment plant: HSV/ExG threshold (`colors.py`) → morphology **open** (despeckle) then **close**
     (fill glare holes) → largest connected component = plant mask.
  2. Detect ArUco (`DICT_5X5_50`, id 0) → pixel-per-mm → convert area px² → cm².
  3. Metrics per frame: area, ROI-fraction, bbox w/h, mask saved alongside.
  4. Volume/biomass: single static camera cannot see occluded layers → for real volume use multi-view
     photogrammetry / stereo → point cloud → surface area & volume (advanced branch).
- **Theory:** §1.3 segmentation & features `315-397`; morphology §5.2 `2111`/`2165`; topology §5.3 `2219`;
  metrics §5.4 `2270`; occlusion problem `279-291` (§3, "3-D reconstruction" remedy `287`);
  geometry/calibration §5.1 `2060`; 3-D reconstruction + LAI `6046`, `6124`.
- **Deliverable:** reproducible projected-area plot over a test series + documented segmentation errors.

### G2 — Disease / symptom detection  (after G1)
- **Goal:** detect **visible symptoms** (chlorosis/paling, necrotic spots, mildew/rust) — not a diagnosis
  (`reflection.md:50`, `reflection.md:120`: observation ≠ confirmed cause).
- **Inputs:** segmentation output (crop the plant/leaf region) + labels; sources limited, so augmentation.
- **Rough method:**
  1. Classical first: hue-anomaly map vs a healthy baseline + spot detection (segment non-green,
     morphology, connected components → count/size spots).
  2. Then a classifier on cropped leaves: ResNet / DenseNet / EfficientNet / ConvNeXt.
  3. Train with strong augmentation — synthetic spots, hue shift to simulate chlorosis; few-shot for rare classes.
  4. Metrics: prioritise **Recall** (missing a sick leaf ≫ a false alarm); **IoU** for masks.
- **Theory:** symptoms list `1859-1861`; classification architectures `1915`, `1477`; augmentation `1641-1642`;
  metrics/Recall-IoU `2307-2322`; ViT attention example `1587`; public dataset (PlantVillage) `2414`.

### G3 — Nutrient / compound estimation  (advanced)
- **Goal:** estimate nutrient status / a chlorophyll proxy. **Honest limit:** RGB can only see a
  *colour-shift proxy*; true compound estimation needs multispectral/NDVI (different camera → the
  deferred advanced branch).
- **Inputs:** the G1/G2 time-series (hue trend, symptom maps) + (later) environment sensors + multispectral.
- **Rough method:**
  1. Track mean leaf **Hue/Cr over time** vs a healthy reference → chlorosis index (N-deficiency cue).
  2. Fuse with environment/EC/pH and an expert-rule base → DSS recommendation (e.g. "+5% N").
  3. Multispectral branch: NDVI/NDRE to read chlorophyll *before* visible symptoms.
- **Theory:** nitrogen → hue `43`, `107-108`; NDVI rationale `132`; multispectral `190-228`; potassium/spectrum `4089`;
  DSS / knowledge base `1942-1943`; LLM report example `1820-1824`.

## (h) Data locations · retention · git policy

**Locations (all gitignored runtime data):**
- Originals: `data/originals/<camera_id>/<zone>/<YYYY-MM-DD>/<UTC-TS>_<sha16>.jpg`
- Sidecar (same stem): `.json` with `sha256`, `captured_at`(device/UTC), `received_at`(server/UTC), dims, byte_size
- Spool (reconnect queue): `data/spool/<sha256>.jpg` + `.json`
- Run log (JSONL): `data/capture.log` · `data/README.md` documents the layout

**Retention / sizing:** `capture_once` never deletes. At 1-min cadence, ~16 h light window ≈ 960 frames/day
⇒ ≈1.0 GB/day @1080p (~0.4 GB/day @720p) (per D3). Plan: rotate/archive old day-dirs and keep downscaled
thumbnails before the disk fills; the pipeline must be able to re-run on old originals.

**Git policy:** code, configs, docs, curriculum, schemas and **small** samples only. **Never commit**
`data/originals/`, `data/spool/`, `data/capture.log`, model weights or the dataset (`.gitignore` already
covers them; `reflection.md:229`, `reflection.md:588`). Large datasets/models live outside the repo with
versioned provenance.
